# SeekNow session — 2026-10-08

The logged-in web client posts to `https://see-know.ru/api/search/stream` with `credentials: include` and body `query` plus `stream: true`. The API dashboard is a different call: `POST /api/v1/search` with `Authorization: Bearer`. Its own page says a key must be generated in Overview first.

`SEEKNOW_COOKIE` uses the stream route. `SEEKNOW_API_KEY` uses the bearer route. Neither value is stored. `/api/v1/stealer` is not called. A 401, a blacklist error, or an error object is not a hit. Do not paste the cookie here.
